# Agent 数据结构控制

UDA-Hub 使用 LangGraph 共享状态 `TicketState` 在各 Agent 之间传递数据。每个 Agent 只负责写入对应的顶层状态字段。

## TicketState 整体结构

`TicketState` 是整个工作流共享的顶层状态，定义为 `TypedDict`，并设置了 `total=False`，因此所有字段在类型层面均为可选字段。字段会随着工作流执行逐步写入。

| 字段 | 类型 | 必需性 | 控制来源 | 解释 |
|---|---|---|---|---|
| `ticket` | `Dict[str, Any]` | 工作流启动时必需 | 外部调用方 | 原始工单数据，是后续各 Agent 的输入来源。 |
| `intake` | `Dict[str, Any]` | 执行 Intake 后存在 | Intake Agent | 标准化问题、摘要、情绪和语言信息。 |
| `classification` | `Dict[str, Any]` | 执行 Classifier 后存在 | Classifier Agent | 问题类型、紧急程度、复杂度及升级建议。 |
| `resolution` | `Dict[str, Any]` | 执行 Resolver 后存在 | Resolver Agent | 自动解决状态、答复、置信度及知识库使用记录。 |
| `escalation` | `Dict[str, Any]` | 仅进入人工升级路径时存在 | Escalation Agent | 提供给人工客服的交接材料和后续处理建议。 |
| `supervisor` | `Dict[str, Any]` | 执行 Supervisor 后存在 | Supervisor Agent | 工作流下一步路由决策及其原因。 |

```python
class TicketState(TypedDict, total=False):
    ticket: Dict[str, Any]
    intake: Dict[str, Any]
    classification: Dict[str, Any]
    resolution: Dict[str, Any]
    escalation: Dict[str, Any]
    supervisor: Dict[str, Any]
```

## Agent 字段控制明细

| Agent | 控制的状态字段 | 字段明细（类型、范围与解释） |
|---|---|---|
| Intake Agent<br>受理智能体 | `intake` | **`summary`**<br>类型：`string`<br>范围：1～2 句话<br>解释：对原始工单的简要概括。<br><br>**`normalized_issue`**<br>类型：`string`<br>范围：清理、标准化后的问题描述<br>解释：去除冗余表达，供分类和解决环节使用。<br><br>**`sentiment`**<br>类型：`string`（枚举）<br>范围：`neutral`、`frustrated`、`angry`、`positive`<br>解释：客户当前的情绪倾向。<br><br>**`suspected_language`**<br>类型：`string`<br>范围：ISO 语言代码，如 `en`、`zh`<br>解释：推测工单所使用的语言。 |
| Classifier Agent<br>分类智能体 | `classification` | **`issue_type`**<br>类型：`string`（枚举）<br>范围：`login`、`billing`、`reservation`、`subscription`、`technical`、`refund`、`other`<br>解释：工单所属的问题类别。<br><br>**`urgency`**<br>类型：`string`（枚举）<br>范围：`low`、`medium`、`high`<br>解释：问题需要被处理的紧急程度。<br><br>**`complexity`**<br>类型：`string`（枚举）<br>范围：`low`、`medium`、`high`<br>解释：解决问题所需的预计复杂度。<br><br>**`should_escalate_immediately`**<br>类型：`boolean`<br>范围：`true`、`false`<br>解释：是否建议跳过自动解决并立即转交人工。<br><br>**`rationale`**<br>类型：`string`<br>范围：自由文本<br>解释：给出上述分类结果的理由。 |
| Supervisor Agent<br>监督智能体 | `supervisor` | **`next_step`**<br>类型：`string`（枚举）<br>范围：`resolver`、`escalation`、`done`<br>解释：决定工作流下一步进入自动解决、人工升级或直接结束。<br><br>**`reason`**<br>类型：`string`<br>范围：简短的自由文本<br>解释：说明选择该路由的原因。 |
| Resolver Agent<br>解决智能体 | `resolution` | **`status`**<br>类型：`string`（枚举）<br>范围：`resolved`、`needs_escalation`<br>解释：表示问题已自动解决，或者仍需人工处理。<br><br>**`answer`**<br>类型：`string`<br>范围：自由文本<br>解释：面向客户生成的最终答复。<br><br>**`confidence`**<br>类型：`number`（浮点数）<br>范围：按当前算法语义为 `0.0～1.0`<br>解释：自动解决结果的可信程度；Supervisor 使用 `0.7` 作为结束判断阈值。<br><br>**`used_kb_articles`**<br>类型：`array`<br>范围：零个或多个知识库文章标识或条目<br>解释：记录生成答案时使用过的知识库文章。<br><br>**`notes_for_human`**<br>类型：`string`<br>范围：自由文本<br>解释：内部处理说明，仅供后续人工客服参考。 |
| Escalation Agent<br>升级智能体 | `escalation` | **`summary_for_human`**<br>类型：`string`<br>范围：自由文本<br>解释：供人工客服快速理解问题的交接摘要。<br><br>**`recommended_department`**<br>类型：`string`<br>范围：部门名称；代码未限定枚举值<br>解释：建议接手该工单的业务部门。<br><br>**`proposed_next_steps`**<br>类型：代码未严格限定，预期为 `string` 或步骤列表<br>范围：一个或多个建议操作<br>解释：为人工客服提供后续处理建议。<br><br>**`include_prior_resolution_notes`**<br>类型：`boolean`<br>范围：`true`、`false`<br>解释：交接材料中是否需要包含 Resolver 之前的处理记录。 |

## 补充说明

- `ticket` 是工作流的原始输入字段，不由上述 Agent 生成或控制。
- 当前 `TicketState` 中各 Agent 对应字段的类型均为 `Dict[str, Any]`。
- 表中的字段类型和取值范围主要由 Agent 提示词约束，尚未通过严格的 Python 数据模型进行运行时校验。
- Supervisor 会读取 `resolution.status` 和 `resolution.confidence`。当状态为 `resolved` 且置信度不低于 `0.7` 时，按当前决策规则结束工作流。
