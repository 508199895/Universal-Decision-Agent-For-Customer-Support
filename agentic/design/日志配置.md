# Python `logging` 通用流程

## 一、创建流

`logging` 的创建流负责搭建日志管道，通常按以下顺序执行：

```text
导入 logging
  ↓
获取或创建 Logger
  ↓
设置 Logger 日志级别
  ↓
创建 Handler
  ↓
设置 Handler 日志级别（可选）
  ↓
创建并绑定 Formatter
  ↓
将 Handler 添加到 Logger
  ↓
开始使用 Logger
```

典型代码：

```python
import logging

logger = logging.getLogger("my_app")
logger.setLevel(logging.INFO)

handler = logging.StreamHandler()
formatter = logging.Formatter(
    "%(asctime)s - %(name)s - %(levelname)s - %(message)s"
)

handler.setFormatter(formatter)
logger.addHandler(handler)
```

创建完成后的关系：

```text
Logger
  ├── 日志级别
  ├── Handler
  │    ├── Handler 级别
  │    ├── Formatter
  │    └── Filter
  └── 父 Logger / Root Logger
```

## 二、执行流

业务代码调用日志方法时，例如：

```python
logger.info("用户登录成功")
```

执行流程如下：

```text
调用 logger.info()
  ↓
Logger 判断是否启用该日志级别
  ├── 未启用：直接丢弃
  └── 已启用：继续
  ↓
创建 LogRecord
  ↓
Logger 执行自身的 Filter
  ↓
遍历所有 Handler
  ↓
Handler 判断日志级别
  ├── 不满足：跳过该 Handler
  └── 满足：继续
  ↓
执行 Handler 的 Filter
  ├── 被过滤：跳过
  └── 通过：继续
  ↓
Formatter 格式化 LogRecord
  ↓
Handler.emit() 输出日志
  ↓
根据 propagation 传递给父 Logger
  ↓
Root Logger 继续处理（如果允许传播）
```

## 三、核心组件

| 组件 | 主要职责 |
|---|---|
| `Logger` | 接收日志、判断级别、分发日志 |
| `LogRecord` | 保存一条日志的完整信息 |
| `Filter` | 决定日志是否允许继续处理 |
| `Handler` | 决定日志输出到哪里 |
| `Formatter` | 决定日志输出格式 |
| `Root Logger` | 所有 Logger 的顶层父节点 |
| `propagate` | 控制日志是否传递给父 Logger |

## 四、级别过滤

日志通常会经历两层级别判断：

```text
Logger 级别过滤
  ↓
Handler 级别过滤
```

例如：

```python
logger.setLevel(logging.DEBUG)
handler.setLevel(logging.ERROR)
```

结果如下：

| 日志调用 | Logger 接收 | Handler 输出 |
|---|---:|---:|
| `DEBUG` | 是 | 否 |
| `INFO` | 是 | 否 |
| `WARNING` | 是 | 否 |
| `ERROR` | 是 | 是 |

最终是否输出，取决于 Logger 和 Handler 中更严格的级别设置。

## 五、多个 Handler

一个 Logger 可以挂载多个 Handler：

```text
logger.info(...)
  ├── StreamHandler       → 控制台
  ├── FileHandler         → 文件
  └── SMTPHandler         → 邮件
```

同一条日志会分别交给每个符合级别要求的 Handler 处理。

常见 Handler 包括：

| Handler | 输出位置或方式 |
|---|---|
| `StreamHandler` | 控制台或流对象 |
| `FileHandler` | 普通文件 |
| `RotatingFileHandler` | 按文件大小轮转的文件 |
| `TimedRotatingFileHandler` | 按时间轮转的文件 |
| `NullHandler` | 丢弃日志，常用于库项目 |
| `SMTPHandler` | 通过邮件发送 |
| `SysLogHandler` | 发送到系统日志服务 |
| `HTTPHandler` | 通过 HTTP 发送 |

## 六、异常日志流

记录异常时：

```python
try:
    1 / 0
except Exception:
    logger.exception("计算失败")
```

相比普通日志，异常日志会额外附带异常类型、异常消息和 traceback：

```text
创建 LogRecord
  ↓
附加异常信息和 traceback
  ↓
Formatter 格式化异常堆栈
  ↓
Handler 输出完整错误信息
```

## 七、项目中的整体链路

本项目的 `logger.py` 可以抽象为：

```text
业务代码调用 log.info()/log.error()
  ↓
Logger（uda_hub）
  ↓
级别过滤（INFO）
  ↓
创建 LogRecord
  ↓
JsonFormatter 转换为 JSON
  ↓
  ├── StreamHandler → 控制台
  └── RotatingFileHandler → logs/uda_hub.jsonl
```

一句话总结：

> `logging` 的创建流是“配置日志组件”，执行流是“过滤、格式化并输出每条日志事件”。
