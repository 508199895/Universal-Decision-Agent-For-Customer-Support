# StylingConfig 版本历史

本文件用于保存 Golden 生成过程中使用过的 `StylingConfig`。历史版本只追加、不覆盖。

## 强制更新流程

每次修改 `StylingConfig` 前必须依次执行：

1. 将修改前的四个字段完整记录到本文件：`scenario`、`task`、`input_format`、`expected_output_format`。
2. 记录版本号、日期、生成通道、修改原因和对应结果副本。
3. 更新 `evals/generate_retrieval_goldens.py` 中的 `STYLING_CONFIG_VERSION`。
4. 更新或新增测试，确保关键提示词内容与通道共享关系符合预期。
5. 运行测试后再生成数据。
6. 每次成功生成时保留：
   - 主结果：`evals/datasets/retrieval_goldens.jsonl`
   - 不可覆盖的副本：`evals/datasets/history/retrieval_goldens_<配置版本>_<UTC时间>.jsonl`

禁止覆盖或修改旧版本条目。若只是修正文案，也必须创建新版本。

## v1：单通道客服配置

- 状态：历史设计版本
- 生成方式：单通道
- 说明：生成普通口语问题，仅在文章适合时补充关键词型问题。

```python
StylingConfig(
    scenario=(
        "真实 CultPass 用户向客服咨询自己遇到的具体问题。"
        "用户使用自然、口语化表达，不使用客服内部术语。"
    ),
    task=(
        "根据知识文章生成客服检索测试数据。"
        "每条问题只描述一个具体用户场景，不包含解决措施。"
        "默认生成普通口语问题；仅当文章确实适合关键词检索时，"
        "才补充自然的关键词型问题。"
    ),
    input_format=(
        "一条简短的英文用户消息。"
        "使用第一人称或自然疑问句，不包含答案提示、排查步骤、"
        "授权条件或升级处理方案。"
    ),
    expected_output_format=(
        "一段客服直接回复用户的英文回答。"
        "只回答当前场景；优先采用上下文中的建议话术；"
        "明确用户下一步动作；不暴露内部授权或升级流程。"
    ),
)
```

## v2：严格双通道配置

- 状态：已生成结果
- 生成方式：每篇文章 2 条语义问题 + 2 条关键词问题
- 修改原因：固定语义与关键词问题配额，并加强关键词问题校验。
- 结果副本：`history/retrieval_goldens_v2_dual_channel_strict_20260920T050336Z.jsonl`

### v2 共享字段

```python
scenario = (
    "真实用户向客服咨询自己遇到的具体问题。用户使用自然、"
    "口语化的英文表达，不使用客服内部术语。"
)

expected_output_format = (
    "一段客服直接回复用户的英文回答。只处理当前问题对应的场景；"
    "上下文中的建议话术能够回答时优先采用；明确告诉用户下一步需要"
    "提供什么或执行什么；不暴露内部授权、审批或升级流程；不作上下文"
    "未授权的承诺。"
)
```

### v2 语义通道

```python
StylingConfig(
    scenario=scenario,
    task=(
        "根据知识文章生成普通语义型客服检索测试数据。每条问题只描述一个"
        "具体用户场景和一个主要诉求，不包含答案、排查步骤、解决措施、政策"
        "结论或升级条件。使用自然口语表达，不要求刻意保留标准术语或精确"
        "关键词。同一篇文章生成的两条问题应体现不同的自然表达或独立场景。"
    ),
    input_format=(
        "一条简短、自然的英文用户消息，使用第一人称或自然疑问句。只描述"
        "用户看到的现象和当前诉求，不包含答案提示、排查步骤、授权条件或"
        "内部处理方案。"
    ),
    expected_output_format=expected_output_format,

```

### v2 关键词通道

```python
StylingConfig(
    scenario=scenario,
    task=(
        "根据知识文章生成关键词型客服检索测试数据。每条问题必须自然保留"
        "至少一个来自标题或正文的精确检索锚点，例如功能名、状态、错误提示、"
        "标准术语、错误码或业务标识。同一篇文章生成的两条问题应尽量使用"
        "不同的检索锚点或不同场景。允许自然使用 reservation_id、"
        "transaction ID 等字段，也可以使用 RES-12345 等合理虚构值。不得"
        "输出 [date]、[type of event]、[platform/system] 等未填充模板，"
        "不得机械堆叠关键词，也不得包含答案或解决措施。问题描述的现象必须"
        "由原文直接支持，不得通过声称某个按钮、功能、状态或选项不存在来"
        "编造新的故障场景。每条问题只描述一个现象和一个诉求，不得同时"
        "询问政策资格、所需材料、排查步骤或完整处理流程。"
    ),
    input_format=(
        "一条不超过 35 个英文单词的自然用户问题，不是关键词列表。问题中必须包含至少"
        "一个与原文一致或高度一致的关键状态、错误提示、功能名或业务标识，"
        "且不得包含未填充的方括号模板或原文没有描述的新故障。只描述问题"
        "本身，不询问应提供哪些资料、应执行哪些步骤或政策是否适用。"
    ),
    expected_output_format=expected_output_format,
)
```
